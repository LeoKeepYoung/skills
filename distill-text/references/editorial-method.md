# 编辑方法与成文标准

## 目录

1. 目标形态
2. 选择与重组

4. 正文段落
5. 长度与密度

## 1. 目标形态

成品应像编辑完成的短篇精编：先用导语介绍来源和核心问题，再用新的小标题组织关键内容。参考文章若采用“背景导入 → 中心问题 → 编辑说明 → 精编正文”的结构，可以复用这一信息架构，但不要复制其标题句式、口头禅、节奏或个人声音。

目标不是：

- 按原顺序逐段缩写；
- 只有项目符号的会议纪要；
- 把原文清理成篇幅更短但结构近似的替代文本；
- 用编辑者的意见覆盖来源观点；
- 为追求传播性夸大冲突或结论。

## 2. 选择与重组

优先保留能完成以下功能的内容：

1. 定义中心问题；
2. 给出核心判断；
3. 解释为什么；
4. 提供最能帮助理解或记忆的例子；
5. 限定结论何时成立；
6. 处理一个真正重要的反例或张力。

删除重复、寒暄、转场套话、与中心问题无关的人名轶事和纯宣传内容。多个相近观点可合并成一个更准确的小节；不要为凑足固定数量拆分同一观点。除非时间演进本身构成论证，否则按概念依赖、因果关系或问题—回答组织，不按原始段落顺序组织。

## 3. 标题与导语

标题优先使用“人物/文本 + 核心问题”或直接表达文章最值得保留的判断。避免“某某文章总结”“干货来了”“看完这篇就懂”等空泛或夸张标题。

导语用两到三个短段完成：

1. 识别素材：谁在何时以什么形式谈了什么；
2. 提出核心问题：这份素材真正试图回答什么；
3. 给出阅读理由：它对哪类读者或问题有何具体价值。

随后用一句编辑说明交代删减、重排、翻译、多个版本或覆盖限制。不要把检索过程写成导语。

## 4. 正文段落

使用四到八个二级标题。标题直接说清本节判断，避免“一、背景”“二、观点”这类无信息标签。正文段落通常完成以下微结构：

```text
观点 → 解释其成立机制 → 最必要的例子或限定
```

一个小节可以有一到三个短段。例子只保留能改变理解的细节；人名、数字和轶事本身不重要时进行概括。素材有鲜明表达时可以保留一句短引语，但不能用连续引语代替编辑。

保持来源的语气强度：建议不要改成规律，相关不要改成因果，个人经验不要改成普遍事实，推测不要改成确定结论。

## 5. 长度与密度

默认约 1200–2000 个中文字符，按用户要求调整：

| 档位 | 建议长度 | 适用场景 |
|---|---:|---|
| 极短 | 500–800 字符 | 快速分享、消息或卡片 |
| 默认 | 1200–2000 字符 | 博客短文、知识库精编 |
| 展开 | 2000–3500 字符 | 复杂长文、多文本综合 |

长度不够时优先减少观点数量，不把每个观点压成没有解释的一句话。长度过长时删除次要例子和重复论证，不删除关键限定。

## 6. 评论模式

默认只做忠实精编。用户明确要求评价、启发或联系现实后，在精编正文之后新增 `## 我的评议`，并明确区分：

- 素材中明确说了什么；
- 编辑者认为哪些部分最有解释力；
- 哪些前提、反例或现实变化可能削弱结论。

不要把评论倒灌进精编正文，也不要把用户尚未表达的观点写成用户感想。
