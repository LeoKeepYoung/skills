# Obsidian 知识连接规则

## 目录

1. 授权与边界
2. 候选发现
3. 阅读笔记语义
4. 连接选择
5. 输出与覆盖说明

## 1. 授权与边界

只读取用户明确确认的 vault 或子目录。路径可以来自当前请求，或同一上下文中已经确认的阅读笔记目录；不得扫描用户主目录猜测 vault。

默认规则：

- 递归枚举确认范围内的 Markdown 文件；
- 排除 `.obsidian/`、`.trash/`、`.git/`、缓存、插件数据、附件和非 Markdown 文件；
- 用户只确认某个子目录时，不越过该目录；
- 只读，不创建索引、不写回 frontmatter、不移动文件；
- 不在答复中暴露与当前文本无关的私人内容、账号信息或绝对 vault 路径。

若用户明确指定知识库目录和阅读笔记目录，分别记录覆盖范围。部分目录不可读时保留已完成的来源总结，并披露第二阶段缺口。

## 2. 候选发现

从第一阶段已经冻结的内容地图生成检索词组，包括核心问题、关键概念、同义词、相反观点、方法名称和重要人物。随后：

1. 使用不会受 `.gitignore` 或隐藏文件规则影响、同时显式排除禁读目录的命令枚举候选；例如在已确认根目录内运行：

   ```bash
   rg --files --hidden --no-ignore \
     -g '*.md' \
     -g '!**/.obsidian/**' -g '!**/.trash/**' -g '!**/.git/**' \
     -g '!**/Attachments/**' -g '!**/attachments/**' -g '!**/附件/**' \
     -g '!**/.cache/**' -g '!**/cache/**' -g '!**/Cache/**'
   ```

   若 vault 使用其他明确的附件或缓存目录名，先加入排除规则再枚举。不要跟随指向确认范围之外的符号链接；
2. 检索文件名、标题、标签、别名、标题层级、wikilink 和正文，而不只匹配文件名；
3. 为同一概念补充同义词、上位概念和常见反例，避免只有字面重合；
4. 形成候选后，完整读取最相关的文件，不根据单个命中片段下结论；
5. 按相关性、笔记属性、具体程度和来源多样性排序，合并重复连接；
6. 从确有依据的候选中选择最多 5 条；可靠候选不足时少给，不凑数。

优先寻找以下关系：相同问题、相同机制、不同领域的同一方法、明确反例、适用边界、前置知识、用户曾提出的疑问，以及可以被当前文本推进的未决问题。

已有语义索引或搜索工具时可以用于召回，但必须回到实际 Markdown 文件全文复核。不要把相似度分数当作连接成立的证据。

## 3. 阅读笔记语义

识别 `reading` Skill 生成的标准章节时，按下列语义处理：

| 位置 | 默认证据属性 |
|---|---|
| `## 我的自由笔记` | 用户直接表述；仍应忠实转述 |
| `## 读中｜讨论快照` 的“我的困惑” | 用户问题 |
| 讨论快照的“达成一致的观点” | 只有明确记为已达成一致时才视为用户认可 |
| `读后｜回看与延伸` 中的真实回答 | 用户直接表述 |
| “直接记录”区块 | 必须逐项判断：用户想法是用户直接表述，讨论中的明确观点是讨论中确认，划线仍是摘录/关注证据；不得按整个区块统一归属 |
| “模式归纳”“谨慎推测” | 生成分析，不等于用户观点 |
| `读前｜进入这本书`、阅读路线、推荐 | 生成内容，除非另有用户确认 |
| 摘录、划线、收藏、书架事实 | 摘录/关注证据，不自动等于赞同 |

普通 Obsidian 笔记若无法判断作者或生成来源，标为“归属未确认”，不要写成“你认为”。

每条输入分开记录“笔记属性”和“连接判断”，不得用一个标签混合两层含义。

笔记属性使用以下之一：

```text
用户直接表述 | 用户问题 | 讨论中确认 | 生成内容 | 摘录/关注证据 | 归属未确认
```

连接判断使用以下之一：

```text
原笔记明示 | 系统直接对应 | 系统推断
```

`原笔记明示` 只用于笔记本身明确建立了当前连接的情况。`系统直接对应` 表示两处有具体、同构的表述但连接由系统建立；`系统推断` 表示还需要一步合理推理。后两者都不得暗示用户亲自建立或认可了这条连接。系统推断必须列出它连接的真实笔记依据，并使用“可能、可以形成、值得对照”等措辞。

## 4. 连接选择

每条连接必须同时满足：

1. 能定位到真实文件及标题或段落；
2. 不只是共享一个宽泛关键词；
3. 能为当前文本增加具体价值，例如支持、反驳、限定、迁移或提出问题；
4. 不依赖暴露无关敏感内容；
5. 措辞强度与笔记属性、连接判断一致。

置信度定义：

- `高`：笔记有直接、具体表述，关系清晰；
- `中`：笔记依据具体，但连接需要一步合理推断；
- `低`：只有弱相关线索，不输出为个人知识连接；可在“没有可靠连接”的覆盖说明中概括为线索不足，但不得据此塑造用户观点。

避免反复引用同一文件。若一个文件确实提供多个不同连接，应解释差异。

## 5. 输出与覆盖说明

按 [短篇模板](../templates/distill-text.md) 的“与我的知识库连接”渲染。每条包含：

- **知识库中的记录：** 忠实转述相关笔记；
- **对当前文本的输入：** 说明支持、张力、边界、迁移或问题；
- **定位：** `[[笔记名#标题]]` 与相对路径；
- **证据：** 笔记属性、连接判断和置信度。

开头用一句话说明实际扫描的目录类别、Markdown 文件数量、完整读取的候选数量和任何覆盖缺口。不要列出无关文件清单或检索词日志。

若没有可靠连接，输出：

```markdown
## 与我的知识库连接

在已确认范围内没有找到足以形成具体连接的笔记。已扫描 <范围与数量>；<必要的覆盖缺口>。
```

不要用通用建议替代个人知识连接，也不要为了显得个性化而推断用户画像。
