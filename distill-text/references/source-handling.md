# 文本获取与覆盖规则

## 目录

1. 一期输入边界
2. 通用覆盖门槛
3. 网页正文
4. 粘贴文本与文本文件
5. 多来源文本

## 1. 一期输入边界

只读取已有文本，不负责从其他载体生成文本。

| 输入 | 一期处理方式 |
|---|---|
| 网页 URL | 打开页面并提取实际正文 |
| 粘贴文本 | 直接读取 |
| `.md`、`.txt` | 读取完整文件 |
| `.html` | 解析主要文本内容，排除页面框架 |
| 用户提供的字幕/转录文本 | 作为普通文本读取 |
| 视频、音频、图片、扫描件 | 不处理；请求用户提供文本 |
| PDF、DOCX 等非纯文本文件 | 不处理；请求用户提供导出的文本 |

不要为视频或音频下载字幕、调用转录服务、分析画面或运行 OCR。网页中嵌入的视频也不属于网页正文；只有页面同时提供的文字稿可以作为文本输入。

## 2. 通用覆盖门槛

先实际读取文本，再判断能否成稿。在内部记录：

```yaml
source:
  title: string
  author: string | null
  publisher_or_site: string | null
  published_at: string | null
  source_type: webpage | pasted_text | markdown | plain_text | html | mixed
  url_or_file: string | null
  length: string | null
  accessed_at: string
  coverage: complete | substantial | partial | unavailable
  locators: headings | paragraphs | lines | none
  limitations:
    - string
```

覆盖程度定义：

- `complete`：正文完整取得；
- `substantial`：缺失部分可识别，且不会改变核心问题、主要观点和重要限定；
- `partial`：只取得片段，缺口可能改变结论；
- `unavailable`：没有取得可总结的正文内容。

总结完整文本时只允许 `complete` 或 `substantial` 成稿，并披露后者的缺口。用户明确只要求某个片段时，可以基于 `partial` 成稿，但标题和导语必须限定范围。

## 3. 网页正文

1. 打开用户给出的规范页面，不把搜索结果摘要当作正文。
2. 识别文章标题、作者、发布日期、更新日期和正文边界。
3. 排除站点导航、推荐文章、广告、页脚和评论；用户明确要求分析评论时例外。
4. 分页文章继续取得所有正文页。动态加载或登录可见内容只在已有授权会话中读取。
5. 页面被拦截、仅显示摘要或正文抓取不全时，尝试同一发布者的打印版、阅读版或作者公开版本；不要用第三方转载静默替代。
6. 无法取得足够正文时，请用户粘贴正文、上传 `.md/.txt/.html` 文件或提供可访问版本。

链接页面中的外部事实不自动成为已核验事实；只有在需要补充背景且实际打开对应来源后才可作为外部核验。

## 4. 粘贴文本与文本文件

- 完整读取用户提供的文本，不按预览片段或文件头部推断全文；
- 保留原有标题、章节、段落和行号作为定位；
- 若文本看似从中间开始、结尾截断或明确省略大段，判断其对结论的影响；
- 用户批注与来源正文混在一起时，先区分两者再提炼；
- `.html` 文件只提取主体内容，排除脚本、样式、导航和模板重复内容；
- 已提供的字幕或转录稿可视为文本，但不要声称已经核验原视频或音频；明显的专名、数字或断句问题进入覆盖限制。

## 5. 多来源文本

先给每个文本指定角色：

| 角色 | 用途 |
|---|---|
| 主要文本 | 决定文章的核心问题和主体结构 |
| 补充文本 | 提供背景、后续发展或缺失解释 |
| 核验文本 | 验证身份、日期、数字或具体事实 |
| 对照文本 | 呈现不同观点、反例或争议 |

分别建立来源归属后再综合。相同观点可合并，但例证和判断仍要能追溯到各自来源；矛盾观点应并列，不用多数投票制造结论。用户未指定主次时，默认把最早提供或正文最完整者作为主要文本，并在导语说明。
