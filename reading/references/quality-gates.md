# Reading 质量门禁

在每个阶段交付或写入文件前执行相关门禁。任何关键门禁失败都应停止该阶段，并说明缺失信息或需要用户确认的事项。

## 目录

1. 通用门禁：身份、证据、隐私
2. 读前门禁：双平台、创作区间、分析、策略
3. 读中门禁：阶段、文件、进度、讨论
4. 读后门禁：完成状态、笔记、推测、三问、输出选题与推荐
5. 结果记录

## 通用门禁

### G0：书籍身份

通过条件：

- 书名、作者、作品形式和目标版本一致；
- 豆瓣与微信读书条目分别绑定具体版本；
- 没有会改变正文、目录或笔记定位的未决歧义；
- 身份置信度至少为 `0.8`。

失败时列出候选和区分点，只询问一个最小确认问题。

### G1：证据与措辞

通过条件：

- 关键事实可追踪到实际打开的来源；
- 搜索摘要未被当作最终证据；
- 作者直接陈述、常见解释、系统推断和开放问题彼此分开；
- 来源冲突和未知信息已披露；
- 没有虚构目录、写作年份、作者意图、划线或用户观点。

### G2：隐私与最小读取

通过条件：

- 凭据、账号标识和无关私密内容未进入仓库、笔记或回复；
- 微信读书书架和笔记只读取当前任务需要的范围；
- 对用户画像的推断有明确依据且与当前书籍相关。

## 读前门禁

### P0：双平台书籍卡

通过条件：

- 豆瓣使用具体 `subject` 页面，记录评分、评分人数、版本和访问时间；
- 微信读书记录 `newRating`、`newRatingCount`、版本和访问时间；
- `readingCount` 没有被当作评分人数；
- 缺失字段写“未取得”，没有从模型记忆补全；
- 没有计算跨平台平均分。

### P1：作者与创作区间

通过条件：

- 作者身份、代表作和关键事件只保留与本书相关内容；
- 构思、写作、完成和出版时间被区分；
- 本书所在创作区间被醒目标记；
- 只有出版年时，没有伪装成完成年份。

### P2：分析机制

通过条件：

- 至少存在一条“环境 → 人的处境 → 作者问题 → 作品”的机制链；
- 作者经历与作品形式/主题之间说明了中间机制；
- 没有以单一经历、时代万能论或人格诊断解释整本书；
- 结果没有退化为作者百科、通史或章节摘要。

### P3：阅读价值

通过条件：

- 目录或章节名来自可核验来源；目录不可用时改用主题或结构位置；
- 书架/笔记关联说明依据和置信度；
- 至少提供一个明确重点、一个观察问题；“阅读提醒”中包含必要的误读纠正、适用条件和迁移边界；
- 阅读方法根据作品与用户目标选择，不机械套用；
- 若微信读书已有精确进度，分析已按常规或回溯式读前正确标记，且没有把目标书已有笔记伪装成读前关联；
- 默认输出符合结构化阅读指南的顺序与版式，没有把检索过程、调试信息或无关生平混入正文；
- 未获阅读确认前没有创建 Obsidian 文件。

## 读中门禁

### D0：阶段确认

通过条件：

- 用户已明确开始或正在阅读；
- Obsidian 目标目录已经由用户指定；
- 目标文件已确认属于同一本书。

### D1：文件安全

通过条件：

- 只更新受管 frontmatter 字段和成对的受管区块；
- 受管标记之外的用户内容保持不变；
- 已有文件没有被整份覆盖；
- 写后 frontmatter、标记、表格和链接均有效。

### D2：进度语义

通过条件：

- 微信读书进度来自精确 `progress`，不是书架更新时间、笔记数或读过标记；
- 手动进度明确标为 `manual`；
- 章节名来自真实目录；
- 重复同步没有制造重复行。

### D3：讨论真实性

通过条件：

- 快照包含“时间、我的困惑、达成一致的观点”；
- 用户未同意时记录“未达成一致”；
- 书中主张、外部证据、用户判断和系统解释没有混写。

## 读后门禁

### A0：完成状态

通过条件：

- 微信读书精确 `progress == 100`，或用户明确确认已经读完；
- 完成时间和来源已记录；
- 来源冲突已由用户确认。

### A1：笔记完整性

通过条件：

- 同时读取全部划线和分页的“我的想法/书评”；
- 分页已经耗尽，或明确披露缺页与失败；
- 数据按章节和时间映射；
- 没有用书签数量臆造缺失正文。

### A2：推测边界

通过条件：

- 用户直接记录、模式归纳和谨慎推测分层；
- 每个推测列出依据并使用适当强度；
- 划线没有被自动解释为赞同；
- 总结连接读前目标、进度、讨论和笔记，而不是泛化画像。

### A3：读后三问

通过条件：

- 三个问题分别检验理解、挑战边界和连接现实；
- 未回答的问题保持待回答或跳过，没有代答；

### A4：输出选题

通过条件：

- 候选数量为 1～3 个，且每个都是具体可输出的题目；
- 每个候选说明核心问题、推荐依据和可选输出形式；
- 推荐依据来自与本书相关且已获授权的画像、笔记、讨论或三问；
- 用户未决定时保持“待决定”，没有自动采纳或直接代写；
- 用户的采纳、暂缓、不采纳或修改意见被忠实记录；
- 没有暴露与选题无关的敏感信息。

### A5：书籍推荐

通过条件：

- 推荐只在用户表示感兴趣后执行；
- 推荐区分同类延展和递进阅读，并排除无意义重复。

## 记录结果

在内部使用以下轻量记录，不要求写入最终笔记：

```yaml
quality:
  stage: pre | during | post
  status: pass | blocked
  passed: [string]
  failed: [string]
  notes: [string]
```

只有本阶段全部关键门禁通过时，`status` 才能为 `pass`。
