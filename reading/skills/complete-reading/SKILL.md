# Complete Reading

在真正读完后完成笔记回扫、体验总结、三问反思、输出选题和可选书籍推荐，并将结果落入同一份 Obsidian 书籍文件。

## 必须先过的门槛

读取 [生命周期协议](../../references/lifecycle-contract.md)、[证据政策](../../references/evidence-policy.md)、[质量门禁](../../references/quality-gates.md) 和现有书籍文件。

以下任一条件成立才可继续：

- 微信读书书架 `finishReading == 1`；
- 微信读书精确 `progress == 100`；
- 用户明确说明已经读完，并允许以手动完成状态继续。

仅仅出现在书架、最近阅读时间、笔记数量或大于 99 的模糊值都不能单独触发；`finishReading == 1` 可以。若书架已标记读完但精确进度不足 100%，状态仍为 `completed`，同时保留并披露真实百分比，不要求用户再次确认。

## 1. 回扫全部个人内容

定位并读取已安装 `weread-skills` 的 `SKILL.md`，再从同一目录读取笔记、书籍与阅读数据能力说明（通常为 `notes.md`、`book.md`、`readdata.md`；若安装包使用 `references/`，则读取其中同名文件）。对目标 `bookId`：

1. 获取真实章节目录；
2. 获取全部划线；
3. 对“我的想法/书评”接口持续分页，直到没有下一页；
4. 按章节和时间把划线、想法与讨论快照对应起来；
5. 记录总数、成功取得数和任何缺页/失败。

“划线”和“我的想法”是两类数据，不能只取其中之一就声称完成全量回扫。书签只能证明存在、但没有正文时，只记录数量与位置，不臆造内容。不要在成品中大段复制受版权保护的原文；使用短定位片段和概括。

## 2. 推测所知所想

分三层输出，严禁混写：

- **直接记录：** 用户的想法、讨论中的明确观点与可定位的划线；
- **模式归纳：** 反复出现的主题、认同、质疑、概念联系和注意力分布；
- **谨慎推测：** 可能的知识变化、尚未解决的张力和行动倾向。

每个推测至少列出依据，并使用“可能、提示、尚不能确定”等强度。划线不自动等于赞同，未划线不等于不重要。

## 3. 总结阅读体验

结合读前目标、作者/背景地图、进度轨迹、全部笔记和讨论快照，回答：

- 用户真正带走了哪些概念、感受、方法或判断；
- 哪些原有观点被加强、修正或保留争议；
- 哪些内容能迁移到用户关心的问题，边界是什么；
- 下一步最值得验证或实践的一件事是什么。

只使用与本书相关、用户已经提供或授权读取的信息。没有证据时不要塑造完整“用户画像”。

## 4. 完成 Top 3 思考

生成三个彼此不同且必须依赖本书与用户笔记才能回答的问题：

1. 一个检验理解与证据的问题；
2. 一个挑战立场、反例或适用边界的问题；
3. 一个连接现实选择、经验或后续探索的问题。

先展示三题，再逐题与用户交互。每题记录用户回答、追问后形成的观点和仍未解决之处。用户可以跳过；未回答的问题保持“待回答”，不得代答。全部回答或明确跳过后，才把最终问答落入“读后三问”区块。

## 5. 推荐输出选题

完成笔记回扫、体验总结和三问后，结合与当前阅读相关且已获授权的用户信息生成 1～3 个候选选题。依据只可来自：

- 用户与本书有关的目标、经历、兴趣或表达偏好；
- 反复出现的划线、想法和知识连接；
- 讨论快照中的共识、分歧与未决问题；
- 读后三问中形成的新判断。

每个选题都应包含：

1. 一个具体、可输出的题目，而不是泛泛的“读后感”；
2. 想回答的核心问题或观点张力；
3. 来自用户画像、笔记或讨论的推荐依据；
4. 一个可选的输出形式，例如文章、分享提纲、播客/视频脚本或实践复盘；
5. 当前决定状态：`待决定`、`采纳`、`暂缓` 或 `不采纳`。

先展示候选并询问用户是否采纳其中一个或多个，也允许全部不采纳或要求改写。得到明确回答前保持“待决定”；不得替用户选择，也不得直接开始创作输出。用户决定后，将选择及必要的修改方向写回“输出选题”区块。

不要为了个性化暴露无关或敏感信息。无法从现有材料形成具体选题时，说明证据不足，并询问用户希望面向谁、以何种形式输出。

## 6. 可选书籍推荐

只有用户表示感兴趣或明确要求时才执行。读取 `weread-skills` 的推荐说明，获取与本书相似或个性化候选；再结合用户本次体验、观点、书架重复项和可靠书目信息筛选。

最多给出两组：

- **同类延展：** 延续主题、文体或问题，但提供不同角度；
- **递进阅读：** 提升理论深度、方法难度或原典距离。

每本说明“为什么适合此刻、与本书的关系、难度/前置要求、推荐依据”。推荐接口返回的是候选，不等于质量背书；需要评分时仍分别注明平台、评分人数、版本和访问时间。排除用户书架已有且无重读价值的书。

## 7. 落档与完成

只更新书籍文件的“读后｜回看与延伸”标准章节，保留用户自由笔记。在进度表中记录完成信号、当时的精确百分比与来源，并在读后章节记录完成时间与完成来源；不得因书架标记读完而把不足 100% 的精确进度改写成 100%。所有阶段的数据来源、缺失、冲突和推断边界都合并到文末唯一的“数据与不确定性”，不在读后章节内再建数据小节。写后检查：

- 数据是否全量分页，失败是否披露；
- 用户原话、事实和推测是否分层；
- 三个问题是否有真实回答或明确的“待回答/跳过”；
- 输出选题是否只有 1～3 个、依据明确，且采纳状态来自用户决定；
- 推荐是否经过用户选择；
- 标准标题和表格是否完整，且没有 YAML frontmatter 或 HTML 管理注释；
- “数据与不确定性”是否只有一处，且是文档最后一个二级章节。

若三问尚未结束或输出选题仍待决定，状态可以保持 `completed`，但读后章节标记为“复盘进行中”，下一轮从未完成的交互继续。

交付前执行质量门禁的 A0–A5；任何关键失败都保持阻断或“复盘进行中”，不得包装成完整复盘。
