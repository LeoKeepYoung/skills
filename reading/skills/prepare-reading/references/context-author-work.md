# Context–Author–Work 分析框架

身份和阅读模式确认后使用本框架。按路由权重控制篇幅，但保持三层之间的因果机制，不退化为百科或摘要。

## 目录

1. Context：作品面对的世界
2. Author：作者的相关视角
3. Work：作品提供什么
4. Reading Entry：转化为阅读入口
5. 范围与禁区

## 1. Context：作品面对的世界

只选择真正影响本书的问题：

1. 确认相关时间、地点和社会、文化、行业、学术、技术或观念环境。
2. 识别一至三个核心张力，例如“复杂信息 ↔ 沟通能力”。
3. 把环境落实到当时人的经验、工作或思想处境。
4. 建立至少一条完整链路：

   ```text
   环境事实 → 人的处境 → 作者面对的问题 → 作品出现的必要性
   ```

删除不能回答“这为何帮助理解本书”的资料。不要写通史、堆年代或把作品全部归因于时代。

## 2. Author：作者的相关视角

只保留与本书有关的身份、经历、代表作和长期问题：

1. 建立作者重要事件与代表作的年份区间。
2. 区分构思、写作、完成与出版；醒目标记本书所在区间。
3. 识别作者反复追问的问题及观察方法，例如逻辑分析、案例归纳、历史比较或第一人称经验。
4. 为关键经历建立：

   ```text
   经历 → 长期问题 → 观察方式 → 本书形式或主题
   ```

每段经历都说明与本书的关系。资料不足时缩短本层，并明确“不对作者动机作推断”。不要远距离诊断人格、用单一经历解释全部创作，或把作者等同于叙述者。

## 3. Work：作品提供什么

先用一个问题描述作品试图回答、展示或解决什么，再按主模式分析：

- `experience`：经验世界、叙述视角、人物处境、形式、语言与情绪结构；
- `argument`：核心命题、术语、概念关系、论证路径、前提、反对对象和结论边界；
- `method`：使用场景、模型、步骤、示例、练习方式和失效条件；
- `knowledge`：基础概念、依赖关系、关键机制、前置知识、难点顺序及理论—实践关系。

说明作品架构中各部分的功能，而不是逐章复述。至少给出：

- 一个明确阅读重点；
- 一个最可能的错误入口及纠正；
- 一个待观察问题；
- 一个适用或迁移边界。

## 4. Reading Entry：转化为阅读入口

压缩一条可解释的主线：

```text
什么样的世界 → 塑造什么样的作者视角 → 产生什么样的作品
```

再把主线转成进入顺序、重点章节或主题、阅读问题、可略读处、不必强求之处和迁移边界。阅读问题要能改变注意力，不要写成考试题或“认真阅读、做好笔记”一类通用建议。

## 5. 范围与禁区

- `metadata_only`：只说明身份和缺失材料，不做作品分析。
- `pre_reading`：使用可靠目录、作者说明、出版社资料和权威评论；文本级判断进入不确定性。
- `text_grounded`：具体结构、语言、意象或论证判断必须绑定章节、页码或用户提供的段落。

只有目录不等于获得全文。不要根据书名、封面文案或常识虚构章节、情节、意象、金句和论证。
