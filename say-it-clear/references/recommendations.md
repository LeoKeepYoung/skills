# 建议生成规则

建议用于把本次会话中的真实问题转化为可练习、可迁移的下一步。不要把报告尾部变成泛化的自我提升清单。

## 选择顺序

依次考虑三类建议，只保留与已确认问题直接相关的类别：

1. **习惯练习：** 默认优先，适合能通过重复动作改善的问题；
2. **专业概念：** 当一个领域概念能帮助用户命名、区分或组织本次问题时使用；
3. **书籍或资源：** 当系统学习的收益明显高于一条即时建议时使用。

总数默认二到四项；每一类默认不超过两项。零建议也是有效结果，尤其是“未发现问题”的报告。

## 习惯练习

每项写清：

- **触发时机：** 用户什么时候执行；
- **具体动作：** 做什么，而不是“多思考”“多练习”；
- **完成信号：** 怎样知道本次做完；
- **对应问题：** 它修复报告中的哪一项差距。

优先设计轻量动作。例如：

```text
实施前四要素检查
触发：准备对 Agent 说“开始做”时
动作：补齐采用项、处理对象、排除项、验收方式
完成信号：四项都能在同一条消息中找到
对应：执行边界分轮补充
```

不要给与材料无关的“每天写日记”“多读多写”等通用建议。不要把一次会话推断成需要长期矫正的习惯；写成“下次可试的练习”，不写成用户已有坏习惯。

## 专业概念

推荐术语的条件：

- 术语能准确命名本次已经出现的现象或提供有用的区分框架；
- 说明中文名、常用英文名、简明定义和本次用法；
- 解释相邻概念的边界，避免只给一个显得专业的标签；
- 依赖领域事实、现行规范或专业定义时，先查可靠的一手或权威来源；
- 无法验证唯一叫法时给描述性说法或候选词，不创造术语。

概念推荐不是新的诊断。例如“验收标准”“Schema exposure”“需求渐进澄清”可以帮助组织问题，但不能仅凭术语存在就反推用户犯错。

## 书籍或资源

只在以下条件同时满足时推荐：

- 主题与已确认问题直接相关；
- 能说清具体读哪一章、哪一部分或带着什么问题阅读；
- 书名、作者和相关内容能够核验；
- 预期收益值得用户投入时间。

每项写清：

- **书名与作者；**
- **为什么与本次问题相关；**
- **建议阅读范围或阅读问题；**
- **它不能替代什么即时行动。**

当书籍推荐会导致无关扩展、无法核验，或一条练习已经足够时，省略。不要为了显得完整而固定推荐《金字塔原理》《思考，快与慢》等常见书；不要声称某本书包含未经核验的具体章节。

若用户明确要求推荐书籍或当前任务本身需要最新书目信息，进行网络核验并引用来源。若无法浏览，只推荐能够可靠确认的经典书目信息，并对具体章节保持克制。

## 输出检查

交付前逐项确认：

- 能指回报告中的某条已确认问题；
- 不是诊断内容的重复改写；
- 没有评分、人格判断或长期画像；
- 没有因一次会话断言用户存在稳定坏习惯；
- 专业概念有定义和使用边界；
- 书籍信息已经核验，且说明阅读目的；
- 没有为了填满三类而制造建议。
