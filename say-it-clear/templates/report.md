# 会话复盘模板

默认输出适合聊天窗口快速阅读的紧凑 Markdown。美化来自信息层级、留白和一致结构，不依赖 HTML、复杂表格、颜色或大量 emoji。

## 排版原则

- 标题之后先给一句话结论，让用户先知道最值得改什么；不要先铺长背景。
- “分析范围”优先用最多三行的两列表格；当渲染器不可靠时改用三条短列表。
- 每个问题使用编号卡片：`01 · 思考` 或 `02 · 表达`，标题直接描述差距。
- 一张问题卡按 `原话 → 诊断 → 影响 → 怎么改 → 改写` 排列。相邻字段内容很短时合并成一段，不重复解释同一事实。
- 原话和改写都用引用块，形成直观对照；只引用判断所需的最短片段。
- 每段默认一到三句。复杂证据才展开，不用长段落制造“专业感”。
- 默认不使用 emoji；需要轻度视觉导航时，全篇最多使用同一套三个符号，不能每个小标题都装饰。
- 不使用嵌套表格、巨型表格或多层列表。表格只承载短元数据，不放长诊断正文。
- 只输出实际命中的可选章节。不要显示方括号占位符、内部分类代码或分析过程。

## 默认紧凑版

```markdown
# 会话复盘

> **一句话结论：** [最重要的一至两个真实发现；没有问题时直接说明]

| 范围 | 说明 |
|---|---|
| 分析对象 | [用户或说话人] |
| 覆盖内容 | [起止消息、轮次或材料] |
| 材料限制 | [没有则写“未发现影响分析的缺口”] |

---

## 01 · 思考｜[用具体差距命名]

**原话**

> [必要的短原话]

**诊断**

[说明问题在哪里及证据性质。]

**影响**

[说明对理解、回答、判断、决策或推进的实际影响。]

**怎么改**

1. [具体思考动作]
2. [必要时的第二步]

**改写**

> [保留原意并补齐思考链的示范]

---

## 02 · 表达｜[用具体差距命名]

**原话**

> [必要的短原话]

**原意**

[只有证据足够时，用一句话重建；原意明显时可省略本字段。]

**诊断与影响**

[指出遗漏、模糊、错排、冗余、衔接或措辞失准，以及造成的实际影响。]

**怎么改**

[说明下次可直接采用的表达动作。]

**改写**

> [保留事实、立场、条件、礼貌和不确定性的完整表达]

**术语边界**

[仅在涉及专业术语、词义边界或多个候选说法时保留。]

---

## 下次直接这样做

- **[动作名]：** [从本次问题归纳的一项具体方法]
- **[动作名]：** [可选第二项]
- **[动作名]：** [可选第三项]

<details>
<summary>未纳入结论的疑点</summary>

- [重要但证据不足的迹象、两种解释，以及还需要什么信息]

</details>
```

如果交付渠道不支持 `<details>`，把疑点改成普通的 `## 未纳入结论的疑点` 章节。没有疑点时整个区域省略。

## 长报告拆分

命中超过三个问题或正文预计超过约 1,200 字时，不要继续堆叠长卡片：

1. 第一屏只放一句话结论、范围和“关键发现”列表；
2. 后续逐条展开问题卡；
3. 最后放“下次直接这样做”；
4. 若渠道支持附件，可将完整证据版放入附件，正文保留摘要，但不要省略关键证据。

第一屏示例：

```markdown
# 会话复盘

> **一句话结论：** 本次最影响推进的不是句子长短，而是实施前没有固定验收标准。

| 范围 | 说明 |
|---|---|
| 分析对象 | Leo |
| 覆盖内容 | 45 条用户发言 |
| 材料限制 | 2 个附件不可读 |

## 关键发现

1. **思考：** 核心术语被纠正后，最终结论仍保留旧概念。
2. **表达：** 实施目标通过多轮追加才完整显现，造成返工。
3. **表达：** “全部”“每一行”等范围量词超过真实需要。
```

## 无问题时

如果没有候选问题通过证据门槛，使用：

```markdown
# 会话复盘

> **一句话结论：** 本次未发现有充分证据、且实际影响理解或推进的问题。

| 范围 | 说明 |
|---|---|
| 分析对象 | [用户或说话人] |
| 覆盖内容 | [实际范围] |
| 材料限制 | [实际限制] |

短句、省略或口语化表达都能由上下文明确恢复，因此不作为问题报告。
```

不要为无问题结果补充通用建议。
